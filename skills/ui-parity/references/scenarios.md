# 对齐场景参考

按本次需求和受影响的组件选用。为相关场景填写具体预期；不要求所有 UI 都支持下面的操作，也不默认所有状态必须等高。

## 状态与布局

| 场景 | 对照内容 |
| --- | --- |
| 首次打开、关闭后重开、切换页签 | 默认页签、状态重置、保留文本、初始焦点 |
| 加载、空数据、请求失败、加载完成 | 标题条件、提示、按钮、状态区尺寸、错误恢复 |
| 少量数据、多条数据、长文本 | 行高、换行、滚动归属、底部操作是否可见 |
| 下拉展开、收起、无结果 | 定位、宽度、提示、遮挡与正文高度 |
| 无选中项、一个、多项 | 标签间距、换行、移除按钮、提交按钮状态 |
| 相关视口尺寸和主题 | 视口限制、样式继承、Portal 样式、溢出 |

区分两个问题：两个界面在同一状态下是否一致；同一界面的不同状态是否应保持相同尺寸。第二项需要需求或基准支持，不能从第一项推导。

例如，把骨架屏改成“加载中”后，还要检查空状态是否有独立的最小高度，以及列表标题是否只在某个状态出现。共用外壳无法保证这些正文条件一致。

## 输入和异步选择器

| 操作序列 | 需要观察的结果 |
| --- | --- |
| 输入普通搜索词 | 文本、查询、候选列表和焦点 |
| 粘贴其他有效账号 | 粘贴后是否保留文本、校验结果、待选标签 |
| 粘贴当前账号、无效值或重复值 | 按业务规则过滤及提示；与正常粘贴分别验证 |
| 输入多个值，如 `alex, beta` | 完整文本、分隔符处理、选中项和未完成片段 |
| 校验尚未完成时继续输入 | 可编辑性、新文本是否保留、旧结果是否覆盖新输入 |
| 点击候选项后继续输入 | 文本是否清空或保留、分隔符、列表和焦点 |
| 移除已选标签，再输入分隔符 | 查询文本与选中状态同步，被移除的值是否意外加回 |
| 清空、关闭、重开 | 旧查询、旧响应、选中项是否按约定保留或重置 |

这些场景的正确结果来自选定基准与用户决定。例如“选择后保留文本”可能是本项目约定，不是所有选择器的通用规则。

控制请求完成时机，使加载和校验期间的场景可重复。先验证普通有效输入，再分别检查权限、自身过滤和无效输入。一次特殊情况复现不能确认用户报告的完整原因。

## 关闭、事件和焦点

| 操作序列 | 需要对照的细节 |
| --- | --- |
| 外部按下鼠标，再释放完成点击 | `pointerdown` 与 `click` 的关闭时机、关键词清理 |
| 操作滚动条或拖动 | 是否被误判为外部关闭 |
| 展开后按 Esc | 下拉是否关闭、文本是否保留、弹窗是否收到事件 |
| 无搜索结果时按 Esc | 与有结果时是否存在不同的事件分支 |
| Esc 收起后再点击仍有焦点的输入框 | 是否重新展开；点击与重新获得焦点分别检查 |
| Tab / Shift+Tab 经过候选项和底部操作 | 可聚焦元素、焦点顺序、焦点是否跳回弹窗顶部 |
| 在 Portal 内操作 | 弹窗焦点范围、外部点击检测和关闭传播 |

抽取时将候选行改成按钮，或更换事件类型，可能改变上述行为。是否保留或改进，需要按需求判断；不要为追求某个历史实现而统一取消可访问性。

## 两组对照记录

沿用项目已有格式也可以。下面只展示字段，实际填写时每个可独立失败的结果各占一行。

```markdown
基准：A；目标：B；其他受影响调用方：C
旧版本：提交及相关未提交内容
改后版本：提交及相关未提交内容
环境：运行方式、视口、缩放、字体、主题、数据与请求时序
允许差异：业务规则及其决定来源

| ID | 界面/状态/操作 | 预期及来源 | 回归：状态/证据 | 对齐：状态/证据 |
| --- | --- | --- | --- | --- |
```

每份证据标识版本、数据、操作和结果。截图对齐同一状态；尺寸记录实际测量值；交互记录操作后的文本、选中项、展开状态或焦点。回归列注明比较的是哪个调用方，不用基准界面的结果代替其他调用方。

同一行不能同时用“未做界面验证”和“通过”描述其 UI 结果。已通过的控制器测试可单列辅助证据；真实控件路径缺失时，该项仍为未验证。
