# 行为覆盖评估 · 2026-11-09

本次评估检查：`repro` 能否从 diff 发现状态和时序缺口，并给出能拒绝回归的判定。评估对象是生成的验收单，不是产品运行结果。

## 方法与输入

使用四次独立子代理运行，每次不继承主会话。代理只获得指定版本的 Skill、原始 Git 仓库和用户任务；不提供 CR 结论、预期用例、评分表或其他运行的输出。主代理在运行前保存检查标准，再人工评阅交付文件。

- 对照输入是精简合成仓库，保留三项变更：移除未归属 extra 的兜底；终态快照优先且刷新键移除保存版本；状态省略时读取键改用文字更新会推进的版本。
- 未变文档提供窗口入口、产品约定、容量预算和历史观察。历史观察仅包含已有 QA、单次大小错误、节点详情重试。文档也明确终态编辑的产品意图未决、图重试争议缺少原触发链。
- 对照任务：对两个冻结提交的精确 `base..head` 范围生成中文手工验收单。
- 简单输入只有四行同步 CLI。任务是为新增 `show --plain` 生成验收步骤；需求为移除 ANSI 并保留默认格式。
- 各代理仅写自己的交付目录。未运行应用。结束后两个输入仓库均保持干净。

原始输入、版本哈希、检查标准和完整输出保存在本机的[评估目录](/tmp/repro-skill-eval-4I4bqj3h)。其中 `inputs.json` 固定比较 SHA，`manifest.json` 固定各版 Skill 的文件哈希，`rubric.md` 是运行前保存的标准。临时文件可能被系统清理；这些链接是本次运行证据，不是跨机器的评估依赖。

## 评估中发现的修正

第一轮新版把手测顺序标为无来源的 P0/P1。它完成了核心覆盖，但该严重性标签没有证据。随后补充规则：手测顺序使用普通排序；事故等级仅引用已有 finding 或仓库标准。

最终新版重新独立运行相同任务，生成八项用例。标题使用“第 1 项”等顺序说明，无自行添加的事故等级；上述八项检查均满足。

简单 CLI 运行生成三项：plain 无 ANSI、默认格式保留、错误子命令保护。没有引入异步、容量、缓存或桌面夹具，也未执行 CLI。此运行使用第一轮新版；最终修订只改变优先级来源规则和模板标题。
