## 结论

SDK 0.27 的 generic `type_text` 可以接收 `element_token` 或 `element_index`。`element_index` 要求匹配的 `snapshot_id`；`element_token` 携带快照上下文。工具描述使用 `AXSetAttribute(kAXSelectedText)` 写入选中文本，和 typed `TypeTextInput` 不是同一个输入形状。

`type_text` 不能作为本次 AX-only 验收路径。它的 `delivery_mode` 只有 `background` 和 `foreground`，描述明确说 AX 失败时可以自动回退到 CGEvent。schema 没有 `strict_route`、`disable_fallback` 或 `ax_only` 字段。结果虽然会报告 `effect`、`route`、`delivery` 和 `escalation`，这些字段是事后结果，不能在派发前阻止回退。

SDK generic `set_value` 是可用的纯 AX 候选。它支持相同的 `element_token`/`element_index` 快照定位，并明确描述对原生文本框直接写 `AXValue`。它没有 `delivery_mode`，也没有 CGEvent fallback 描述。对每个字段，验收仍必须检查返回结果为 `route: "accessibility"` 和 `effect: "confirmed"`；不能只看调用成功。

Generic `click` 的 element-token 路径是第二个候选。其描述说明 AX action path 不移动光标、不抢焦点。对提交按钮使用 `delivery_mode: "background"`，并要求结果为 `route: "accessibility"`、`effect: "confirmed"`。因此，在独立测试桌面中，`set_value` 三个字段后再用 token AXPress 提交，可以构成完整的纯 AX 表单验收候选。

产品现在提供 `Computer.setValue(target, elementToken, value): Promise<AxValueResult>`。它只调用 generic `callTool("set_value")`，传递 `pid`、`element_token` 和值；不会调用 `typeText` 或键盘事件。返回结果必须同时是 `route: "accessibility"` 和 `effect: "confirmed"`。其他 route、缺失结构化结果或未知结果会标为 unknown，并使 session 不可继续使用。批处理、持久 exec 和 CLI `act --set-value VALUE --element-token TOKEN` 都通过同一个 seam。

## 可运行验收 runner

[computer-use-ax-form.ts](../../scripts/probes/computer-use-ax-form.ts) 已补齐为独立、可选的闭环 runner。无参数运行只输出 guard report，不加载 SDK、不编译或启动 fixture；native 运行必须同时提供 `--allow-native` 和 `--test-desktop LABEL`，并使用一个尚不存在的 `--out-dir`：

```sh
bun scripts/probes/computer-use-ax-form.ts \
  --allow-native --test-desktop isolated-login-session \
  --out-dir /private/tmp/yk-ax-form-run
```

runner 会编译并启动该 fixture，读取一次完整 AX observation，从同一份真实 observation 取得 Name、Email、Message 的 token，串行调用产品 `Computer.setValue`，再用新的 AX observation 验证三个字段，最后通过产品的精确 AX token click 路径提交，并验证 AX result=`submitted`、fixture `submitCount=1`。fixture 只接受 `{"quit":true}` 生命周期命令，不能侧写字段值。`observation-*.json` 是表单主要证据，`state-*.json` 只记录 fixture 的只读生命周期辅助证据。

当前 `Computer.click` facade 只返回投递结果，不暴露 typed SDK 的 route/effect，所以 runner 会把提交 route 记录为 `unavailable`，并把 `inputIsolation` 标为 `unverified`、`desktopInputSent` 标为 `unknown`。提交后的 AX 业务结果可以验收表单闭环，但不能把这个结果解释成派发前严格 AX-only 的输入隔离证明。runner 不调用坐标、type、key、scroll 或 activate。

## 独立桌面候选流程

这只是后续验收流程，不能在当前用户桌面执行：

1. 在独立测试桌面编译并启动 fixture。确认 state 中 `ignoresMouseEvents=true`、`isKeyWindow=false`、`isMainWindow=false`，并记录测试桌面原有 frontmost pid。
2. 读取一次目标窗口 AX snapshot，保存三个字段和提交按钮的 `element_token` 以及 `snapshot_id`。每个后续 token 必须来自同一个窗口和同一份新鲜 snapshot。
3. 对 Name、Email、Message 分别调用 SDK generic `callTool("set_value", JSON.stringify({pid, window_id, element_token, value}))`。每次只接受 `route=accessibility`、`effect=confirmed`；若返回其他 route、escalation、refusal 或未知结果，立即停止，不重试、不切 foreground。
4. 重新 observe，确认三个字段的 AX 值准确变化，窗口仍是非 key/non-main，frontmost pid 没有变化。
5. 用提交按钮 token 调用 generic `click`，参数为 `delivery_mode:"background"`。只接受 AX route 和 confirmed effect。
6. 重新 observe，确认 AX result 字段为 `submitted` 且 submit count 为 1；同时保存 state.json 作为辅助证据。
7. 通过仅含 `quit` 的 control 文件退出 fixture，关闭 SDK/session，并记录清理结果。

该流程如果在独立桌面通过，可以证明产品 `setValue` seam 对这个标准 AppKit fixture 的 AXValue 写入，以及现有 token AXPress 的效果。它不能证明所有应用或 Web 内容都支持 AXValue。若 SDK 返回其他 route 或没有确认结构，产品会 fail closed；背景标签、frontmost 状态和事后截图不能替代 route/effect 结果。

现有失败证据仍见 [native acceptance](2026-09-16-native-acceptance.md) 和 [raw type result](evidence/2026-09-16-native/type-diagnostic/raw-type.json)：此前 typed background type 返回 `unverifiable`、`synthetic_events`、`background`，并建议 foreground；本轮没有重新执行该输入。
