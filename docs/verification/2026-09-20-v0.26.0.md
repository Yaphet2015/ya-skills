## 失败记录与 CI

第一次默认测试碰到仓库里残留的 `dist/release`（`0.25.3` 可执行文件）。`tests/computer-e2e-release.test.ts` 在产物存在时会跑打包闭环，于是 `ykVersion` 期望 `0.26.0`、实际 `0.25.3`。该次失败不计为通过，日志为 `tests-stale-dist-failed.txt`。删除本次无关的 `dist/yk` 与 `dist/release` 后重跑。未删除其他版本的压缩包。

清除旧产物后的第一次完整默认测试失败 1 项：`exec terminal reduction > terminal receipt closes admission for every queued independent RPC`（`batchCalls` 期望 ≤1，实际 2）。单独重跑该测试 8 次均通过。下一次完整默认测试通过，见上表。原始失败日志在整理证据时被覆盖，摘要见 `tests-flake-note.txt`。这是 flake，不是第一次就通过。

[标签工作流](https://github.com/Yaphet2015/ya-skills/actions/runs/35517140335) 因发现已上传产物而跳过后续步骤，状态为 success。`ci.json` 与 `ci-release-run.json` 保留各步骤状态。这不代表 CI 执行了测试；发布依据是上述本地检查。

检查时没有打开的 Release Please PR，也没有其他打开的 PR。未合并任何 PR。

## 发布操作

先提交并推送版本号 `0.26.0`。打标签前核对已跟踪文件干净，HEAD 与远程 main 均为测试提交。通过 `gh release create v0.26.0 --target 718d5817f296116aec41125026a3b112263e9412` 上传压缩包和 `.sha256`，没有覆盖旧版本。

重新下载并比对通过后，使用 `scripts/update-ya-skills-formula.py` 更新公式 URL、哈希和版本断言，再提交推送 tap。Homebrew 升级时设置 `HOMEBREW_NO_INSTALL_CLEANUP=1`，保留旧版本供排查。

发布证据与产物分开保存。本次压缩包、编译文件以及解压和下载目录在所有检查通过后清理；GitHub Release 保留可下载产物。
