# Computer Use：批处理、视觉兜底和代码执行设计草案

日期：2026-09-14。状态：设计范围已确认，实施计划已编写；未开始实现。

实施入口：`docs/superpowers/plans/2026-09-14-computer-use-agentic.md`，下分 desktop、sessions、exec 三份子计划。

研究依据：`docs/research/openai-computer-use-optimizations.md`。本文件修正研究报告中把“AX 优先”误写成已有完整视觉兜底、把截图映射笼统称作性能优化的问题。

## 1. 已确认需求

- 全部纳入：视觉坐标点击、可选截图缩放与坐标换算、短动作批次、按需观察、本地条件等待、持久会话、代码执行运行时、验证和文档。
- 脚本按受信本机代码执行，不建设 VM、容器或 OS 权限沙箱。
- 本轮只做设计和计划；不操作真实桌面，不开始实现。

## 2. 成功定义

1. AX 能可靠识别目标时优先 AX；AX 信息不足但截图有效时允许外部 LLM 看图并给出坐标。
2. 确定的短动作序列只调用一次工具，执行结束后统一返回观察；本地检查不必逐次返回 LLM。
3. 一个任务内复用 driver；代码调用之间可保存显式数据状态。
4. 代码执行无需额外模型依赖；不新增模型审计、权限分类器或脚本批准系统。
5. 部分执行、未知投递、取消、恢复均有明确结果，不把整个请求重新执行。
6. 通过相同任务的对比实验验证效率；不预先承诺 Token 或耗时下降比例。

## 3. 本机执行与可靠性边界

### 3.1 不提供额外安全边界

按用户最新裁定：取消独立快速模型审计，不新增脚本安全性判断或权限系统。代码按受信本机代码执行。普通子进程、Node vm、受限 globals 不是沙箱。

代码可能读写文件、访问网络、启动进程，也可能使用桌面应用中已登录的账号。本能力不提供脚本权限隔离。

不保证代码无法绕过 computer facade。只把 facade 内操作声明为可追踪，不声称捕获全部本机副作用。

### 3.2 保留执行可靠性控制

- 独立进程、硬超时、取消和进程组清理；不是安全沙箱。
- computer facade 检查目标、动作预算、截图新鲜度和投递结果，不分类业务风险。
- 宿主生成动作事件，不信任脚本自行打印的成功声明。
- 状态目录、socket 和日志仅当前用户可读写；不监听 TCP。
- runtime 不主动收集凭证。任意脚本自行打印的敏感数据无法保证自动识别，文档说明限制。

### 3.3 能力接口

只定义请求输入、执行结果、观察数据、会话生命周期和错误恢复，不依赖调用方的运行环境或权限实现。

exec 是本机代码执行接口，可以包含多步操作，不是只读工具或单次点击接口。不新增模型调用、审计配置或批准回调协议。

本轮沿用 CLI 和 Skill 入口，不另建 MCP server。

## 4. 推荐架构与替代方案

推荐：现有 runtime 增加桌面原语和 batch；新增会话宿主与脚本 worker，CLI 仅负责解析/输出。不增加内部审计层或调用方运行时适配层。

替代 A：每次命令临时运行一个批次。实现最少，但不能满足跨调用状态复用和代码运行时需求。

替代 B：直接接通用 REPL，不管理会话和请求状态。实现短，但无法可靠处理忙碌目标、未知投递及进程回收，不采用。

### 模块归属

- `packages/computer-runtime`：SDK adapter、AX/视觉观察、坐标换算、动作原语、batch、预算及投递结果。
- 新增 `packages/computer-session`：同用户本地会话、目标占用、请求去重、事件存储、脚本 worker 生命周期。通过 workspace import 调用 runtime。
- `packages/functions-computer-use`：session/exec/batch 请求的编排、CLI 参数和结果。
- `packages/functions-computer-e2e`：继续复用 runtime，使用新的点击/观察能力；保持既有受信 E2E 套件执行契约。
- `packages/cli`：保留命令注册；增加最小内部自启动入口分发，不放领域实现。
- `skills/computer-use`：外部 LLM 的操作规则；不在 yk 内再造一个完整视觉规划 agent。

## 5. 观察和视觉点击

### 5.1 分离有效性

新观察接口分别记录 AX 和图片状态，区分 usable、empty、degraded、truncated、unavailable 及原因。空树不能被默认为完整有效；图片存在也不代表可操作。

显式 AX-only、image-only、AX+image 模式。保留现有 snapshot 对严格 AX 的兼容语义；新观察路径支持图片有效、AX 不足的情况。

权限错误、目标消失、窗口身份不确定、实际截图无效不能用视觉降级绕过。取消“degraded 一律代表隐藏”的过度推断；原始 SDK 状态如实保留。

### 5.2 坐标约定

外部 LLM 指定的是返回图片上的像素点。点击请求必须携带 observationId，不能只提供无来源坐标。

每份观察保存：目标身份、时间、图片原始尺寸、发送尺寸、窗口原点与尺寸、输入坐标单位、缩放变换。macOS 截图像素与输入点数的关系必须先探针验证，不能只假定乘 2。

执行前验证 observationId 所属 session、目标和几何状态；截图过期、窗口移动/缩放、滚动/导航后拒绝沿用旧坐标。按键/输入后的坐标也不得无限复用；批次内确定动作的可复用范围需明示。

仅几何检查无法发现全部 UI 内容变化。视觉点击仍有残余误判风险；未知状态先重新观察。

### 5.3 缩图

默认不缩图。新增可选发送尺寸上限，保持宽高比，不放大；原图保留为证据。只支持缩放，不在本轮额外引入裁剪。

图片 detail 由外部 agent/API 控制，yk 返回尺寸和映射信息，不承诺本地文件会改变模型的 detail 设置。

坐标映射属于正确性要求；减少图片分辨率才可能节省图像 token，需实际测量。

## 6. Batch 与本地等待

- 有序动作：AX 点击、视觉点击、输入、按键、滚动、本地条件等待。
- 同一批次绑定一个目标窗口，禁止并行驱动。
- 开始前校验完整请求结构和静态预算，避免执行到中途才发现格式无效。
- 每步执行前做动态条件检查，必要时读取本地 AX；这些读取无需逐次回传 LLM。
- AX 点击继续 fresh lookup 和唯一匹配，不能缓存 element token。
- 焦点状态只使用可验证元数据；SDK 当前 WindowElement 没有通用 focused 字段，selected 不等于 focused。需要显式焦点断言时，无法验证返回 unsupported_condition 并转回观察；普通 click→type 可以批处理，但不声称焦点已经被本地可靠验证。
- 默认短批次，建议初始 5 个动作；这是本项目可调策略，不是 OpenAI 公布阈值。设置整体和单步时间限制。
- 正常完成返回一次最终观察；失败返回已完成步骤、失败步骤、未执行步骤和能安全获得的现场。
- 步骤结果区分 delivered/not_delivered/unknown；delivered 不等于业务成功。
- 条件等待只接受受限结构化谓词，如唯一元素存在、值匹配、窗口可用；不在 batch 中偷偷引入任意 JS。
- 任何需要新的 LLM 判断的步骤是批次边界；返回观察后再提交下一批请求，runtime 不自动识别业务风险。

## 7. 持久会话与脚本执行

### 7.1 会话

建议公开命令形态：`session open/status/close`、`batch --session ID --file ...`、`exec --session ID --file ...`。既有 act/perceive 保持可用，新增可选 session 参数。

同一会话顺序处理操作；忙碌时拒绝并发 mutation。目标占用跨 session 检查，活动会话持有目标 lease；不能因为断线或超时就立即偷走 lease。

每个请求有 requestId、内容 hash 和宿主事件记录。同 ID 同内容仅返回既有状态，不重复执行；同 ID 不同内容拒绝。重启后未终结请求标记 unknown，不自动恢复执行。

空闲回收仅适用于没有在途动作的 session。崩溃、取消后确认 worker/原生操作已退出或终结，才能释放目标。无法证明安全时报告阻塞，不立即启动第二个 driver。

### 7.2 代码运行时

本轮支持 JavaScript；不同时建设 Python/Playwright 第二套桌面后端。脚本通过现有 computer runtime 控制桌面，支持 await、循环、条件、本地等待和显式观察。

推荐脚本 API：`computer`、`target`、`state`、`log()`、`observe()`。state 为显式 JSON 数据，保存到宿主；不依赖跨请求保留任意闭包/异步后台任务。脚本单次运行在可终止子进程中，driver 留在 session 宿主管理的专用原生 worker 以复用初始化；原生阻塞不应阻塞宿主的取消和状态接口。

脚本调用 computer facade 经私有 IPC 交给宿主执行。脚本结束后禁止旧请求继续操作；取消时拒绝剩余 RPC。终止脚本不意味着已投递的原生动作撤销，必须遵守 unknown 处理。

输出包括有界日志、观察引用和宿主生成的动作记录。图片不作为 base64 混入文本日志。输出超限、执行超时、无限循环都有明确错误，不能只靠 Promise.race 假装终止同步代码。

脚本能绕过 facade 使用其他本机接口，这是受信执行的残余风险；只把 facade 中的操作声明为可追踪，不声称捕获全部本机副作用。

## 8. 兼容性、分发与文档

- desktop primitive 只在 computer-runtime；SDK 继续 lazy load，help/list/install 不加载 native。
- Bun 基线保持仓库的 1.3.14；执行脚本能否在编译后的 yk 中运行必须先做探针。
- 不要求 Homebrew 用户额外安装 Node/Bun。优先自启动打包后的 yk；若不可行，先报告证据并调整分发方案，不悄悄加 PATH 依赖。
- runtime sidecar 必须通过现有 package:release 生成；同步源码、编译 binary、Homebrew sidecar 验证。
- E2E 默认测试保持 desktop-free，更新生成 API 声明和相关事件 union，不破坏 events.jsonl 的 SSOT。
- README、computer-use 文档、skill、安全说明、错误恢复示例和研究报告中的不准确描述一起更新。

## 9. 实施分解与依赖

详细测试优先实施计划已按以下三个子项目组织，避免一个巨大任务同时改所有边界；接口和任务以关联的实施计划为准。

### A. 桌面执行基础

1. SDK 与编译执行可行性探针：坐标、图片/AX 分离、焦点、后台投递。
2. 独立观察状态、图片元数据与缩放纯函数测试。
3. 视觉点击及新鲜度检查，保留 AX 点击。
4. Batch、局部条件等待、部分执行结果及预算。
5. 单步 CLI/E2E 接口兼容和文档。

交付：不依赖新会话服务即可使用的一次性 batch 和视觉兜底。

### B. 持久会话

6. 私有 socket 协议和 session 宿主，自启动入口。
7. 请求去重、事件落盘、目标 lease、退出/回收/崩溃语义。
8. CLI 接入与编译分发验证。

交付：driver 复用、多轮批次运行，无脚本执行也能独立使用。

### C. 代码执行

9. 脚本 worker、宿主 RPC、显式 state、硬超时及取消。
10. exec 输入输出契约、分段执行示例、未知投递恢复端到端测试。
11. 性能基准、真实桌面验证、全部文档和发布回归。

交付：exec 复用会话，无新增模型依赖；全部需求在同一套 runtime 上闭环。

## 10. 验收矩阵

### 无桌面测试

- AX 找不到但图有效；AX 截断；权限拒绝；图片缺失。
- 1x/2x 和非整数缩放，边界/负数/非有限坐标，窗口移动/缩放和过期观察。
- Batch 第 N 步失败后其余步骤不执行；动作已送达但最终观察失败不重放。
- 焦点变化、唯一目标变多、状态等待超时、请求预校验无副作用。
- exec 请求参数无效时不执行脚本；有效请求无需额外模型或审计配置即可执行。
- exec 无限循环、取消、超量日志、旧 RPC、worker crash、宿主重启。
- 重复请求、冲突 hash、跨 session 目标竞争、lease 保守回收。
- runtime 默认元数据不收集凭证；文档和 skill 明确脚本输出的隐私责任及屏幕内容不代表授权。
- 更新 computer-e2e 类型生成及事件 reduction 回归。

### 发布与真实桌面

- typecheck、默认测试；如有跳过项逐项列出，不说全部通过。
- package:release、现有 YK_RELEASE_TESTS=1 门禁、新增打包会话/exec 的无桌面协议验证、build、smoke。
- 用户指定非敏感测试窗口，覆盖 AX 表单、视觉画布/无 AX 区域、Retina、窗口变化、批次中断及后台不抢焦点。
- 对相同任务比较单步、batch、持久 batch、exec；记录模型回合、观察/截图数、driver 初始化次数、p50/p95 耗时、失败率和恢复情况。
- 可获取真实模型 usage 的基准记录 Token；无法获取时标记未知，不用文件字节数冒充 Token。
- 不修改本机全局权限，不自动登录，不以真实发送/删除验证风险动作；用 fixture 和受控 UI 代替。

## 11. 实施默认值与静态检查细化

默认选择：受信本机执行、JS 单语言、不新增模型审计、显式 JSON state、默认不缩图、短批次默认上限 5、不引入本地视觉规划模型。这些不是已实现能力。

- SDK 0.27.0 已声明 Coordinates、maxDimension 和 screenshotScale/windowBounds；类型声明不是原生行为验收。
- 第一版保存原始PNG，显式缩图用系统sips生成同帧派生图；不引入新的native图像包。坐标单位仍由前置探针验证。
- 新增 observe 接口，旧 perceive/snapshot 保持严格语义，避免兼容性回归。
- 跨命令观察需要新帧几何及原始PNG hash验证；编码变化可能保守误拒绝，不能声称像素级比较。
- 宿主管理独立原生worker，使原生调用异常不堵塞控制面；脚本worker另行可终止。
- SDK README 的implicit session可能五分钟无活动结束；本轮session空闲上限两分钟，不自动复活旧driver状态。
- 目标占用按应用进程而非仅窗口互斥，避免同app共享焦点；单步CLI/E2E/session复用同一lease实现。

实现前置探针、类型签名、文件和测试在子计划中列明；探针失败时先报告受影响范围，不以规划文本代替实测。
