## 结论

三个问题都有证据支持，但需要分开归因：

1. 有文件选择框之外的主动前台切换。主要来源是 Agent 写出的 AppleScript，而不是日志已证明 CUA 在后台调用中偷偷激活应用。

## 2. token 与速度

### 长历史一直留在主循环

L624 第一次桌面调用已携带 162,393 输入 token。到 L1132 已约 306,008。前一次 compaction 在 L385，下一次在 L1135，整个桌面诊断阶段没有 compaction。L623 之前的文档、实现、上传问题分析都继续占用上下文。

窗口内有 222 次 bash 工具返回。命令文本中出现 observe 46 次、act 37 次、windows 25 次、batch 1 次，没有 session/exec 调用。这里是命令出现次数，循环可能执行多遍，也包含 help 请求，不能当作成功动作数。

主循环反复执行“写命令 → 返回 → 重新推理”。同一份约 24 万 token 的上下文在 252 次请求中重复使用，解释了约 6093 万累计 token。不能把这个数字理解成生成了 6093 万字的回答。

检查 9 个实际产生新模型消息的视觉分叉，按 message id 排除从主会话复制的记录，新增消耗为：输入 940,998；缓存 1,445,504；输出 3,105；合计 2,389,607 token。

调用没有显式选择 fresh。当前 pi-subagents 实现支持 `context: "fresh"`，省略时可由配置或 agent profile 决定 fork。未确认历史配置具体来自哪一层，因此不将其归因成平台无条件默认 fork。

### 明确的失败放大器

- **组合键契约不清楚：** L635、637、643 共记录 6 种组合键写法被拒绝。CLI 将整串 `Cmd+Alt+I` 当作 key 传给 SDK；当前 runtime 和 batch/exec 支持独立 modifiers，单步 CLI 没有对应参数。
- **观察结果结构用错：** L646–651 从顶层读 `elements`、`observationId`，实际位于 `observation.ax.elements`、`observation.id`。结果被误读为没有元素。act 和 observe 的返回形状不同，也增加了误用概率。
- **错误上下文进入模型：** L625 的整行 apps JSON 为 9,110 字符；对单行 JSON 使用 grep/head 不能筛掉其他应用。L641 意外列出截图缓存目录，输出 16,072 字符。
- **截断或丢弃错误：** 多次使用 `>/dev/null`、`head -c 100`，丢掉了动作返回和错误细节；随后又重新 observe。
- **重试判断错误：** L693、1088 用字符串是否包含 `error` 决定重试，但实际拒绝文本为 `the window changed...`。L694、1089 都只执行了 try1 就退出。
- **视觉等待超过截图有效期：** L1080→1083 等待约 96 秒；L1085 明确拒绝“older than 60s”。
- **截图比较过于严格：** L692、694、1087、1089 在新截图后仍被拒绝。当前实现对窗口几何和整份 PNG 的 SHA-256 做精确比较（`session.ts`、`observation-store.ts`）。任意像素或 PNG 编码变化都可能拒绝。日志没有保存足够证据确定具体变化源，不能直接认定是光标闪烁。
- **持续试探未切换路径：** DevTools 输入在 06:47–06:52 UTC 反复失败；文件框在约 08:12–08:22 UTC 反复失败。最终转向代码注入，说明长时间 UI 试探没有直接推进诊断。

这些问题互相放大：步骤变多使 token 增加；视觉等待使截图失效；重复截图与拒绝又促使 Agent 绕到前台 AppleScript。

## 建议顺序

1. **先调整路由和上下文。** 网页先探测 CDP、绑定具体 tab/target；网页表单和调试通过 DOM/CDP，原生窗口再使用 computer-use。视觉 worker 显式 fresh，只提供图片、问题、坐标约定。桌面任务提供精简任务状态，避免带着全部开发历史运行。
2. **补齐命令契约。** 提供组合键参数和可复制示例；统一或明确 act/observe 的输出 envelope；输出精简的结构化错误、执行状态和下一步。失败重试依据错误码和退出码。
3. **降低每步调度开销。** 已确定的连续操作用 batch/exec；保留动作返回的 observation；相同原因连续拒绝后切换路径，停止无限试键和猜焦点。
4. **改善截图证据验证。** 验证应同时检查窗口身份、几何和目标区域是否仍然有效，容忍无关局部变化。不能仅删除过期保护或全屏比较。视觉返回已超期时，重新确认目标再点击；单纯延长 TTL 不足以解决状态变化。
5. **把前台回退做成可观测能力。** 记录动作前后 frontmost PID、输入路径、拒绝原因；确需前台时合并操作并恢复实际原前台。将 AppleScript 激活也纳入同一策略，避免主模型绕过 CLI 的约束。

这些是修复建议，尚未实现或进行真实桌面回归。
